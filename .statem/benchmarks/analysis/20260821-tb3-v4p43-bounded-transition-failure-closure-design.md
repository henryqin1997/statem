# TB3 v4p43 bounded transition-failure closure

## Evidence basis

The v4p42 heat-pump development cell reached a valid family route, two
candidate cycles, independent reviews, quarantine, and candidate-bound replay.
It then recorded eleven identical blocked `solve -> falsify` transitions. The
retry brief contained a concrete validation delta, while the new preflight
plan represented its semantics only through shorter labels. The machine gate
correctly required the exact discriminator and blocked the transition.

Four host resume sessions remained in the same solve entry. Each session's
entry-scoped Stop hook allowed repeated unchanged attempts, and the generic
resume prompt did not assign the immediate mechanical repair to the test
planner. This was a host lifecycle closure defect. It was not a reason to
weaken the gate, rewrite the candidate, or add a task-specific practice.

## Minimal repair

v4p43 combines the v4p42 family-scoped public artifact practice with a small
host-side transition-feedback mixin. It leaves the shared v4p35 runbook,
family router, StateM core, and promotion semantics unchanged.

The bounded transition receipt now records:

- a stable blocker fingerprint scoped to the current entry;
- the repeated-attempt count and whether the repair budget is exhausted;
- an immediate failure class, repair owner, and bounded repair action; and
- redacted first-line evidence for at most four blocking checks.

For an exact validation-delta failure, the immediate owner is `test_planner`.
The next same-context prompt tells that role to read the immutable retry brief,
append its exact `validation_delta.discriminating_check` to one candidate-blind
`required_strata` list, regenerate preflight evidence, and rerun only the
failed gate. The underlying implementation failure ownership remains intact.

When a transition blocker is present, its fingerprint dominates unrelated
artifact or draft churn in the host progress identity. v4p43 permits one
same-context repair session and one Stop-hook continuation per entry in that
session. A changed state or changed blocker is progress; an unchanged blocker
ends fail-closed as protocol-invalid instead of consuming more candidate or
review cycles.

## Matched-cell rule

The first v4p43 Heat cell is adapted development evidence, not a fresh score
estimate. It validates failure closure only if an exact-delta block either
repairs and advances or terminates after the bounded attempt with an exported
owner-specific receipt. The public artifact practice advances only if the
declared bundle is harvested or a narrower independently replayable owner is
established. Raw reward and protocol validity remain separate.
