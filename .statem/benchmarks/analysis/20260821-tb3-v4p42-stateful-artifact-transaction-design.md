## Minimal control

v4p42 derives from the last validated v4p39 adapter. It leaves the shared
v4p35 runbook and StateM core unchanged. The only behavioral increment is a
`public_artifact_transaction` check in the existing `stateful-systems`
reviewer profile. It requires the selected reviewer to:

- bind each task-visible output to its producer context and external handoff;
- establish existence, non-emptiness, parseability, and harvest continuity
  before making semantic claims;
- when public summary and event artifacts coexist, derive only schema-visible
  identity, ordering, terminal-state, and conservation checks; and
- keep missing production, failed handoff, malformed output, structural
  disagreement, and domain-semantic disagreement as separate owners.

The practice is loaded only when contract audit selects `stateful-systems` as
the primary or secondary profile. Solver and reviewer receive the selected
profile, while unrelated task families do not. No expected task answer,
service endpoint, file path, or verifier information is encoded.

## Promotion rule

The first matched StateM cell is adapted development evidence, not a fresh
score estimate. It advances the control only if the two public artifacts are
successfully harvested or if a narrower independently replayable owner is
established. Raw reward remains separately reported. A second
hypothesis-scoped no-progress result parks the task.
