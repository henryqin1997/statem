# TB3 v4p80 stateful route audit addendum

This append-only note was created after the matched KV pair launched and before
either result was observed. It does not change the preregistered raw comparison.

The visible-instruction selector routes six tasks to
`stateful_lifecycle_compact`. WAL, MVCC, KV, and payments are plausible members.
The same broad trigger also routes React through `service + consistency` and
Bun through `server + visibility`. React has a preserved direct raw one, so
automatic activation under the current family trigger carries false-heavy
negative-transfer risk.

Consequences:

- A KV direct-zero/StateM-one result would establish positive transfer only for
  the exercised KV/stateful subrange.
- It would not authorize setting the current broad family route to admitted.
- Production activation remains blocked until positive and negative route
  examples support a narrower observable subfamily trigger.
- The raw pair, artifact identity, and protocol verdict remain interpreted
  exactly as preregistered.
