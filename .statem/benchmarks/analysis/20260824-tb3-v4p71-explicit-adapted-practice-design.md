# TB3 v4p71 explicit adapted practice activation

## Purpose

Production v4p70 activates only admitted family practices. Develop mode still
needs a bounded way to test one unadmitted practice after attribution identifies
a falsifiable family-level hypothesis. v4p71 adds an explicit adapter argument
for that purpose only.

The host computes the normal visible-instruction selection and requires its
practice id to equal the declared development id. A mismatch fails before
StateM or Codex starts. A match records `explicit_adapted_development` and runs
the unchanged 86-line thin graph with only the compact solver obligations. It
does not load the detailed reviewer catalog, independent reviewer graph,
promotion stack, or another family.

## ERP hypothesis

The prior ERP matched cell was direct raw zero and heavy-StateM raw zero. Its
candidate-bound public replay passed, but the detailed reviewer treated
incomplete population evidence as a reason to quarantine the candidate. The
new falsifiable hypothesis is that compact lifecycle guidance plus ordinary
verify/revise/handoff preserves a potentially useful candidate without the
false-heavy evidence gate.

This is a second adapted control hypothesis, not repetition of the old one. A
raw one supports family transfer. A raw zero may still justify another adapted
proposal only if the public artifact or state path yields a new discriminator;
otherwise ERP is parked for this generation.
